# judge

Grades answers against ground truth, and builds the question the agent is asked.

- `checks.py` — The question text, the system prompts and answer format the agent gets, the recorder that runs a starter or reference fix against a local stand-in to see the request it sends, and the answer grader (`grade`).
- `obkit.py` — The obkit hooks: `grade`, `verify` (the LLM verifier, which never changes a score) and `key_check` (whether an accepted request appears on its docs pages).
- `config.yaml` — The verifier's two readers (Claude Haiku 5.5 reads every answer; Claude Sonnet 5.5 reads again where Haiku disagrees or is unsure), their prices, and the cost of one verified answer.
- `cases.jsonl` — Planted answers with the verdict the grader must give.
- `verifier_prompt.txt` — Prompt for the LLM verifier.

## What the answer grader checks

The answer grader in this repo (`checks.grade`, called from `judge/obkit.py`) passes an answer when its call matches one of the question's right calls. For REST, that means the same method and path, and the call must expand every name the right call expands: each top-level name in an `$expand` in its address, and the name in its `require_query` field. A placeholder in a right call's path matches any text: a whole segment, or the part of one it stands for, as in `Entity_{templateId}` for an API that puts a customer's template id in the entity name. Keys in parentheses must have the same names (or both be written by position); a key value the right call writes out, such as `('ACTIVE')` when the ticket names that record, must be the same without quotes or case, while a placeholder or an empty value matches any value. A right call with `match: prefix` names a service root, and any path under it matches. For SOAP, it means the same operation sent to a Workday service that publishes it; a key lists one right call per such service.

A right call may list `fields`: the query parameters, body fields or SOAP request elements its call must name, and, written `name=value`, the value the ticket states for one. A field is listed when the ticket asks for that content, under the name the docs give it for that call: in the public question `hard_sn_queue_uxa_export`, "for January 2025" lists `from_date=2025-01-01` and `to_date`, "limited to the modern workspace experience" lists `channel`, and "click activity" lists `name_filter=click`. A value the ticket states in a query option, such as `$top=1` for one record, is a field too, since the grader reads the address query only for `$expand`. An alternate route or operation that makes the request lists the fields under its own documented names; a request format asked for by `$format`, which a header can set as well, is not listed. Fields the ticket calls optional, containers the ticket does not name, and paging the ticket does not ask for are not listed; a ticket that only says what an operation must support lists nothing. Names compare without case or punctuation, and each dotted, indexed, slashed, spaced or quoted part of a field the agent names counts, so `items[0].quantity` names `quantity`. A listed value must be the value the call gives for that name (`name=value` or `"name": value`), the same without case or punctuation; a date may carry a time after it, and a placeholder or a list of choices is no value. A value the ticket leaves to the caller is never listed.

The grader does not read the key's `required_query` or `with` fields, or any header.
